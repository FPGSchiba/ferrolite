## 1. Goal & validation

Kill the **visible tile buildup** in the full-res viewer and finish the sparse-VT quality/perf
work the architecture map filed under Spec 4.5:

> On **first load** and **after an edit**, the user must never see tiles assembling on screen. The
> previous coherent image stays until the new full-res frame is fully composed **off-screen**, then
> the composed image is **swapped in atomically**. During pan/zoom the smooth fit-preview is shown
> and the sharp full-res is swapped in only once motion settles and the frame is complete. LOD
> transitions are smoothed so there is no blurry→sharp pop, and no display pipeline is ever rebuilt
> on interaction.

This is the "swapchain" fix (map §4.5 item 5.1) plus full **tiling refinement** (B) and a
**pipeline-caching audit** (C). Image quality remains secondary to speed/architecture (map §3.3);
this adds *presentation coherence and perf*, not new image science.

### 1.1 Why the buildup happens today (grounded in the code)

- The full-res tier is the **rung-4 sparse VT** (`ferrolite-vt` `display.wgsl` `fs_sparse`),
  presented **directly** into the egui swapchain pass every frame via the viewer callback
  (`ferrolite-app/src/viewer/callback.rs`).
- Tile production (`produce_view`) fills the VT **pool** (a GPU array texture) incrementally
  across frames. Because `draw_sparse` runs **every** frame while the pool is still partly filled,
  the user watches the pool fill: non-resident tiles paint a flat `vec4(0.05, 0.05, 0.05, 1.0)`
  and the per-fragment **coarse-LOD fallback** resolves neighbouring fragments at different levels
  → visible tile boundaries + blurry→sharp popping.
- The existing crossfade (`tick_crossfade`, `CROSSFADE_SECS = 0.15`) gates only the **initial**
  preview→full reveal on `tiles_settled`; subsequent edits, and any pan that makes tiles
  non-resident, re-expose the buildup.

The key realization: **tile production is already off-screen** (it writes the pool, not the
swapchain). What is seen is the **on-screen draw of a not-yet-complete pool**. The fix is to stop
presenting the pool until it is whole — and to do so via a real off-screen present buffer so the
swap is atomic and crossfadable.

## 2. Scope

**In:**
- `ferrolite-vt` — `PresentBuffers` (off-screen double buffer, engine-tier), a `present.wgsl`
  fullscreen blit + its `DisplayPipelines` entry, **trilinear LOD** in `display.wgsl`, a CPU-rect
  **convergence predicate**, **prefetch + protected coarse base** and eviction tuning in the
  residency/request path, and a **pipeline-build counter** guard.
- `ferrolite-gpu` — a generic off-screen render-target/blit helper **only if** it belongs at this
  tier (generic, photo-agnostic); the retained-DAG executor is **not touched**.
- `ferrolite-app` — the viewer present path: drive the present state machine, compose `back`
  off-screen, swap + crossfade, wire a dev-mode profiling hook. No photo concepts pushed down.

**Out (non-goals / other phases):**
- Any photo-domain behavior — new edit ops, color changes, lens work (4.4), export (4.2) (map §4.5 "Out").
- Reworking the generic executor, the `TileSource`/`TileProducer` seams, or edited-tile versioning
  semantics (§5.3 stays as Spec 2 defined it — this phase only *consumes* it).
- HDR/wide-gamut presentation precision (the display tail is already applied in the shader; the
  present buffer uses the existing display `target_format`).
- Disk shader cache (`wgpu::PipelineCache`), multi-format pipeline caching (Spec 3/1 YAGNI stands).

## 4. The present model — the "swapchain" (A)

### 4.1 `ferrolite_vt::PresentBuffers` (new, engine tier)

A photo-agnostic double buffer of two **canvas-resolution** color textures in the display
`target_format`:

- `front` — the currently presented, **complete** frame.
- `back` — the frame being composed this convergence cycle.

Sized to the viewer canvas (not the whole monitor); recreated on canvas resize. Cost ≈ `w·h·4`
bytes each — ~15 MB at 2560×1440, ~30 MB for the pair — negligible against the ~1–2 GB tile pool
budget. This is generic "double-buffered presentation of a rendered view"; it holds no photo
vocabulary and is liftable into the engine.

```
pub struct PresentBuffers { /* front, back: wgpu::Texture + views; size; target_format */ }
impl PresentBuffers {
    pub fn new(ctx: &GpuContext, size: (u32, u32), target_format: wgpu::TextureFormat) -> Self;
    pub fn resize(&mut self, ctx: &GpuContext, size: (u32, u32));
    pub fn back_view(&self) -> &wgpu::TextureView;   // off-screen compose target
    pub fn front_view(&self) -> &wgpu::TextureView;  // blit source
    pub fn swap(&mut self);                           // front <-> back (role swap)
}
```

### 4.2 What renders where

- **Tile production is unchanged and invisible** — `produce_view` keeps filling the pool over
  frames at `Visible` priority (Spec 2 §5.2), cancellation on nav/edit unchanged.
- **Off-screen compose:** on the frame the pool becomes **converged** for the settled
  viewport + `opstack_version` (§4.4), the app records **one** off-screen render pass that invokes
  `draw_sparse` into `back`. Because the pool is converged, `back` is a complete image — no partial
  tiles. This render is off-screen, so its composition is never seen.
- **Present** (the egui callback `paint`) becomes a **blit** of the chosen source into the swapchain
  via a new engine-tier `present.wgsl` fullscreen pass (§4.5).

### 4.3 Present state machine (pure, tested unit)

Extracted like the existing `ViewTransform`/crossfade units so it is verifiable without a GPU.

| State | Presented source |
|---|---|
| Interacting (pan / zoom / **slider drag**) | **Preview** (rung-1 `draw_single`), transform-aware, smooth, edit-current |
| Settled, full-res not yet converged | Preview (held) while `back` composes off-screen |
| Convergence just reached | **Crossfade** preview → `front` over `CROSSFADE_SECS` (reuse `tick_crossfade`) |
| Settled + converged | **`front`** blitted 1:1 (rendered at the current transform — no resampling) |

Inputs: `interacting: bool`, `full_ready: bool`, `converged: bool`, `crossfade_factor: f32`.
Output: `PresentSource { Preview, Crossfade(f32), Front }`. The transition from `Preview`/held into
`Crossfade` fires the frame `converged` first turns true; `Crossfade` → `Front` at factor ≥ 1.0.
Any `interacting` edge (new drag, edit) returns to `Preview` and clears convergence.

### 4.4 Convergence signal (drives the swap)

The CPU `needed_tiles(viewport, transform, level_count)` (already used by rung-3) enumerates the
`(lod, x, y)` tiles the **settled** viewport requires. **Converged** ≔ every needed tile is resident
**at the current `opstack_version`** in the pool (reuses `VersionedResidency::to_produce(needed)` →
empty). This is an **immediate CPU predicate** — it does not wait on the 1-frame-latent GPU feedback
(§5.3), so the swap is not dragged out.

On the converged frame: record the off-screen compose into `back`, then begin the crossfade; at
crossfade end `PresentBuffers::swap()` makes `back` the new `front`. The double buffer keeps the old
`front` live on screen throughout the crossfade window.

### 4.5 `present.wgsl` blit (new, engine tier)

A trivial fullscreen-triangle pass sampling one source texture into the swapchain, with an optional
`alpha` uniform for the crossfade blend. Its pipeline + bind-group layout are added to
`DisplayPipelines` and **pre-warmed at startup** (§6). The preview branch keeps using the existing
rung-1 `draw_single` (which is transform-aware); the blit is used to present `front` 1:1 and to
alpha-blend during the crossfade. Output is already display-encoded (the tail runs in
`fs_sparse`/`fs_main`), so the blit is a straight copy/blend — no color work.

### 4.6 Edit interaction (§5.3, unchanged semantics)

A slider drag is `interacting`, so the live preview already shows the edit at preview-res during the
drag (Spec 2 §6 two-tier recompute). On release: the `opstack_version` bump + stale-tile eviction
plumbing runs as today; new-version tiles converge off-screen (§4.4); we crossfade preview → sharp
`front`. No pre-edit sharp frame needs preserving — the preview covers the transition — so the
double buffer is justified by the **crossfade window** (both buffers live), not by retaining a stale
sharp frame.

### 4.7 Fallback / error handling

- Off-screen target allocation failure → revert to today's **direct-draw** present (logged); no panic.
- GPU device/surface loss → recreate `PresentBuffers` alongside the VT pools, then re-request the
  visible tiles (extends Spec 1 §9).
- Canvas resize → `PresentBuffers::resize` at the new size; convergence recomputed for the new viewport.

## 5. Tiling refinement (B)

### 5.1 Prefetch + protected coarse base

- Keep **one coarse base LOD fully resident and protected from eviction**. This guarantees the
  coarse-LOD fallback in `fs_tiled`/`fs_sparse` always finds a resident tile — so the
  `vec4(0.05,…)` gray is never reached in practice — and makes convergence fast (the base is always
  there to compose under refinement).
- Prefetch a **1-tile ring** around the viewport and the **next zoom level's** tiles at
  `Background` priority, so a subsequent pan/zoom has data ready and `back` composes quickly.
- Prefetch computation (ring extent, base-level selection) is a **pure tested function** in
  `ferrolite-image`/`ferrolite-vt` (no GPU).

### 5.2 Eviction tuning

LRU stays (`ResidencySet`), with two added rules: **never evict the protected coarse base level**,
and **never evict a current-version tile the presented `front` depends on**. Budget stays
configurable against the pool VRAM budget. Eviction ordering with the base protected is a pure
tested unit.

### 5.3 Feedback-pass latency (split the two jobs)

- **Static convergence** — the predicate that gates the swap (§4.4) — is driven by the **immediate
  CPU `needed_tiles` rect**, so there is no 1-frame wait before the swap can fire.
- **GPU feedback** (the rung-4 readback) continues to drive **exploratory** streaming + prefetch
  during motion and catches anything the rect estimate misses. Off-screen convergence may raise
  `MAX_PRODUCE_PER_FRAME` (the buildup is invisible) but stays **bounded and profiled** so a single
  compose frame does not blow the frame budget.

### 5.4 LOD smoothing (kills the popping)

Change `fs_tiled`/`fs_sparse` from **hard** LOD selection to **trilinear**: sample the picked LOD
*and* the next-coarser LOD (both resolved through the existing coarse fallback, both guaranteed
resident by the §5.1 base prefetch) and blend by the fractional LOD `fract(log2 d)`. Engine-tier
shader change, **no photo concepts, no new pipeline variant** (same `fs_sparse`/`fs_tiled`
pipelines). The blend fraction is a pure tested helper.

## 6. Pipeline-caching audit (C)

- **Confirm build-once, make it a guarantee.** The Spec-4.5 code sweep found no
  rebuild-on-open/interaction paths. C adds a **pipeline-build counter** on the pipeline-creation
  path, asserted against the expected count after pre-warm (a `debug_assert` + a headless test), so
  any future accidental per-frame/per-open pipeline creation trips immediately.
- **New pipelines join the cache.** The `present.wgsl` blit pipeline + its bind-group layout are
  added to `DisplayPipelines::new` and **pre-warmed at startup** alongside the existing four display
  variants (`Single`/`Tiled`/`Streaming`/`Sparse`). The trilinear change adds **no** variant.
- **Profiling.** A **dev-mode** per-frame GPU/CPU timing hook measures pan/zoom frame time against
  the budget (≤ 16.6 ms @ 60 fps target) on the dev GPU at target zoom; measured numbers are
  recorded in §9. This satisfies the CLAUDE.md "profile anything that could exceed a frame budget"
  rule for this surface.

## 8. Testing

Mirrors the VT ladder's split (Spec 1 §10): pure CPU logic runs green in CI (no GPU); GPU output is
covered by golden diffs on the dev GPU, auto-skipped when `GpuContext::headless()` returns `None`.

- **Pure CPU (CI-green; 80%+ on non-GPU logic):**
  - Convergence predicate: needed-set all resident at the current version → converged; a version
    bump or a missing tile → not converged.
  - Prefetch-ring + protected-base computation; eviction ordering with the base protected and
    front-dependent tiles pinned.
  - Trilinear blend-fraction math (`fract(log2 d)`, clamping at the top level).
  - **Present state machine:** every transition in §4.3 (interacting↔held↔crossfade↔front) and the
    crossfade factor ramp; edit/nav edges reset to `Preview`.
- **Golden GPU diffs (dev GPU, auto-skip headless):**
  - Trilinear LOD output vs a committed reference (within the existing per-pixel tolerance).
  - **`blit(front)` is byte-identical (within tolerance) to a direct `draw_sparse`** when the pool
    is converged — proves the present indirection changes nothing when complete.
  - Crossfade midpoint (`alpha = 0.5`) blend of preview and `front`.

## 9. Acceptance criteria (measured on the dev GPU, then hold for the author's visual test)

1. **Zero visible tile buildup** on first load and after an edit — author-confirmed visual (the
   held preview stays until the composed sharp frame swaps in; no tiles seen assembling).
2. **Fluid pan/zoom within frame budget** — pan/zoom stays ≤ 16.6 ms/frame (60 fps target) at target
   zoom on the dev GPU, **profiled** (§6), and the **pipeline-build counter** proves no pipeline
   rebuild on interaction. *(Measured numbers recorded here during implementation.)*
3. **No LOD popping** — trilinear golden passes and the blurry→sharp snap is gone (visual).
4. **Workspace gate green** — `cargo fmt --check` + `cargo clippy --workspace --all-targets -- -D
   warnings` + `cargo test --workspace` — **then STOP and hold for the author's hands-on visual
   test** before finishing/merging (CLAUDE.md §3.4).

> **Derived outcome (not a separately-gated criterion):** because the coarse base is always resident
> (§5.1) and the preview is shown during any non-converged/interacting state, the `vec4(0.05,…)`
> bare-gray fill is never presented in normal operation.

## 10. Build order (TDD; each step demoable)

1. **Pure units first** (tests → impl): convergence predicate, prefetch/eviction math, present state
   machine, LOD-blend fraction.
2. **Trilinear LOD** in `display.wgsl` + golden.
3. **`PresentBuffers` + `present.wgsl` blit** + `DisplayPipelines` entry + pre-warm; the
   blit-equals-direct-draw golden.
4. **App wiring:** off-screen compose of `back`, swap + crossfade, present-source selection driven by
   the state machine.
5. **Prefetch / protected-base / eviction + CPU-rect convergence** live in the viewer request path.
6. **C:** build-counter guard + dev profiling hook; profile a pan against the budget; record §9 numbers.
7. **Workspace gate green** → hold for the author's visual test.
