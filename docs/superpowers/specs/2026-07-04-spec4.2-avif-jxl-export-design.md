## 1. Goal & validation

Add **AVIF** (lossy) and **JPEG-XL** (lossless) as two more output formats behind the *existing*
Spec 3 encode core, with **zero new C toolchains**. Everything else is reused unchanged:

> open/edit an image → the Spec 2 GPU tile producer renders it full-res tiled → `working→output`
> conversion + OETF + quantize (`ferrolite-color`) → optional resize → **encode** — now one of six
> formats, the two new ones being AVIF and JPEG-XL — → best-effort EXIF copy + ICC → written to
> the destination by the same `ferrolite-jobs` **Background** export job. Both the single
> **Photo → Export** popup and the batch **Export module** gain the two formats automatically.

Image quality remains **secondary** to speed/architecture (map §3.3): this proves *format
breadth*, not new color/quality science. The deliverable is the two encoders slotted cleanly into
the settled encode tail with no engine-crate or contract drift.

---

## 2. The central decision: pure-Rust encoders (no C toolchain)

The map framed 4.2's central open question as "how the libjxl C toolchain is gated so CI and
contributors without it still build." **We avoid the toolchain entirely** by choosing pure-Rust
encoders, which resolves the gating question by making it moot:

| Format | Crate | Kind | Modes | Bit depth | ICC embed |
|---|---|---|---|---|---|
| AVIF | `ravif` (rav1e) | **pure Rust** | lossy (quality + speed) | 8-bit | ✗ (high-level API) |
| JPEG-XL | `zune-jpegxl` (+ `zune-core`) | **pure Rust** | **lossless only** | 8-bit / 16-bit | ✗ |

**Why this over libjxl (`jpegxl-rs`):**

- **The CI gotcha that reframed the question.** `.github/workflows/ci.yml` runs
  `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all` on
  `windows-latest` + `macos-latest`. Because CI passes **`--all-features`**, a default-off
  `jpeg-xl` Cargo feature would still be **turned on in CI** — so a feature flag alone would *not*
  spare CI from libjxl's `cmake`/`clang` toolchain. Pure-Rust deps need no gating and CI stays
  green with **no workflow change**.
- **Project ethos.** Image quality is explicitly secondary (map §3.3); the workspace is already
  all-Rust (the only JXL code in-tree is `jxl-oxide`, a pure-Rust *decoder* pulled transitively by
  `rawler`). Keeping the build toolchain-free matches the "keep it clean" discipline.
- **Trade-off accepted:** **no lossy JPEG-XL** (zune-jpegxl is lossless-only and self-describes as
  a "POC encoder" — functional and standards-valid, modest compression ratios). This also
  **resolves the map's "whether JXL lossless is offered" question**: lossless is the *only* JXL
  mode. A future spec may add lossy JXL via libjxl behind a real toolchain decision; explicitly out
  of scope here.

**Decided (brainstorm 2026-07-04):** pure-Rust only; `ravif` + `zune-jpegxl`, both always-on, no
feature flags, no `libjxl`.

## 3. Crates, tier & dependencies

- **`ferrolite-export`** (photo tier) — adds `ravif` and `zune-jpegxl` (+ `zune-core`), both
  **permissive pure-Rust** crates. The existing four formats keep using the `image` crate.
- **`ferrolite-app`** — the format combo + a new Effort control in the shared settings form; the
  persisted-format DTO gains the two variants + an effort field.
- **No engine-crate changes. No feature flags. No `cmake`/`clang`/`libjxl`.** CI is unchanged and
  stays green under `--all-features` on Windows + macOS.

## 4. Encode-core extension (`ferrolite-export`)

The change is surgically small and lives entirely in the encode tail.

### 4.1 `options.rs` — formats + Effort

`ExportFormat` grows from 4 → **6** (`Avif`, `JpegXl`):

- `ExportFormat::ALL` becomes a 6-element array (drives the UI combo automatically).
- `extension()`: `Avif → "avif"`, `JpegXl → "jxl"`.
- `label()`: `Avif → "AVIF"`, `JpegXl → "JPEG-XL (lossless)"`.
- `supports_quality()`: now `Jpeg | Avif` (AVIF is lossy).
- `supports_16bit()`: now `Tiff | Png | JpegXl`.
- **new** `supports_effort()`: `Avif` only.

New effort type + field:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Effort { Fast, Balanced, Best }   // default Balanced

impl Effort {
    /// ravif speed: 1 = very very slow / max compression, 10 = fast / larger.
    /// Best is deliberately 3 (NOT 1) to avoid pathological export times.
    pub fn ravif_speed(self) -> u8 {
        match self { Effort::Fast => 10, Effort::Balanced => 6, Effort::Best => 3 }
    }
}
```

`ExportOptions` gains `pub effort: Effort` (default `Effort::Balanced`). `effective_bit_depth()`
is unchanged: it already forces 8-bit whenever the format is not in `supports_16bit()`, so AVIF is
always 8-bit and JXL honors 16-bit.

### 4.2 `encode.rs` — two new match arms

The existing `Jpeg | Png | Tiff | WebP` arms are untouched (still `image` crate encoders with
best-effort `set_icc_profile`). AVIF/JXL **bypass the `image` crate**: they build an encoded
`Vec<u8>` in memory and write it to `dest`. `RenderedImage`/`PixelData` (8-bit or 16-bit RGB)
already carries the correct pixel data.

- **AVIF** (8-bit RGB): `ravif::Encoder::new().with_quality(opts.quality as f32)
  .with_speed(opts.effort.ravif_speed()).encode_rgb(Img::new(rgb8, w, h))` → write
  `EncodedImage.avif_file`. (If `PixelData::Sixteen` ever reaches here it is down-quantized to
  8-bit first; `effective_bit_depth()` prevents it in practice.)
- **JPEG-XL** (8-bit or 16-bit): `zune_jpegxl::JxlSimpleEncoder` with
  `ColorSpace::RGB` and `BitDepth::Eight`/`Sixteen`; for 16-bit, pass `PixelData::Sixteen` as
  native-endian bytes (`bytemuck::cast_slice::<u16, u8>`). Encode to a `Vec<u8>`, write to `dest`.

`ExportError::Encode(String)` covers encoder failures; the write uses the existing
`ExportError::Io` mapping. Never panics.

### 4.3 ICC & EXIF on the new containers (the one honest wrinkle)

- **ICC embedding:** neither `ravif`'s high-level `Encoder` nor `zune-jpegxl` exposes ICC
  embedding, so AVIF and JXL are written **untagged**. Pixels are still fully converted to the
  chosen output space (default sRGB), so they display correctly in the common case. This is exactly
  the Spec 3 §10 "ICC emit failed → valid-but-untagged file + warning" fallback, made always-on for
  these two formats: when `opts.embed_icc` is true and the format is AVIF/JXL, push **one**
  informational warning ("ICC embedding not supported for AVIF/JPEG-XL; file is untagged") — never
  silently drop it. A future enhancement could inject ICC for AVIF via `avif-serialize`; out of
  scope.
- **EXIF copy:** `copy_exif` (via `little_exif`) is attempted for every format as today; if the
  container is unsupported it fails **best-effort into a warning** (existing behavior — no new
  code). Never fatal.

This preserves the never-panic / best-effort contract (Spec 3 §10) and is honest about the limits.

## 5. App UI (`ferrolite-app`)

### 5.1 Shared settings form (`export/settings_form.rs`)

- The **Format** combo lists all 6 automatically (it iterates `ExportFormat::ALL`).
- The **Quality** slider already keys off `supports_quality()` via `add_enabled_ui`, so it lights
  up for AVIF with no extra code.
- **New Effort selector** — a segmented `Fast / Balanced / Best`, wrapped in
  `add_enabled_ui(o.format.supports_effort())` so it is only active for AVIF. Placed next to
  Quality.

### 5.2 Per-control reset note

CLAUDE.md's per-control-reset rule targets the **Develop editing** controls (sliders, tone curve,
crop, HSL). The export **settings** form is a configuration surface and does **not** use reset
arrows today (the existing Quality slider has none). The new Effort selector follows that
established convention — a segmented control with an obvious default (`Balanced`) — rather than
introducing a reset arrow inconsistent with its neighbors. *(Confirmed acceptable in brainstorm.)*

### 5.3 Persistence (`settings/dto.rs`)

- `PersistedFormat` gains `Avif` / `JpegXl`.
- New `PersistedEffort { Fast, Balanced, Best }` mirroring `Effort`.
- `PersistedExport` gains `#[serde(default)] pub effort: PersistedEffort` — older persisted
  settings lacking the field deserialize to the default; **no data loss** on upgrade.
- `from_options` / `to_options` extend for the new variants + effort; the existing
  `export_roundtrip_all_variants` test grows to cover AVIF/JXL and effort.

Both the single `Photo → Export` popup and the batch Export module get the new formats + Effort
for free (they share `settings_form`).

## 6. §5 cross-cutting contract compliance

1. **Job submission is universal** — unchanged: export is still one `ferrolite-jobs` **Background**
   job with priority + cancellation + progress; the new encoders run inside the same worker
   closure (`run_export`).
2. **Catalog is a cache** — untouched (no catalog change).
3. **Decode yields separable products** — untouched (no decode change).
4. **GPU executor is photo-agnostic** — untouched: no `Graph<PipelineImage>` edit; the render path
   is reused verbatim.
5. **VT is source-agnostic** — untouched (no VT change).

**Licensing (§3.1):** both new deps are permissive pure-Rust crates in the **photo tier**; the
engine-transferable crates (`ferrolite-jobs`/`-gpu`/`-vt`/`-image`) are unchanged and stay
copyleft-free.

## 7. Error handling (extends Spec 3 §10; never panics)

- **Encoder failure** (AVIF/JXL) → `ExportError::Encode` fails that one export with a status
  warning; a batch continues with remaining images.
- **ICC not embeddable** (AVIF/JXL) → valid untagged file + one informational warning (§4.3).
- **EXIF copy unsupported/failed** (any format) → best-effort warning (§4.3).
- **Write failure** (path/permission/disk) → `ExportError::Io`, surfaced per-image; never fatal.
- **Cancellation** → checked once per tile during render (unchanged); encode is post-render.
- Job panics are caught at the existing worker boundary; one bad export never downs the pool.

## 8. Testing (TDD; CLAUDE.md gate, then hold for the author's visual test)

**Pure-CPU / logic tests (every OS in CI — the 80%+ target):**

- `ExportFormat` table for all 6: `extension`, `label`, `supports_quality`, `supports_16bit`,
  `supports_effort`; `Effort::ravif_speed` mapping (Fast→10, Balanced→6, Best→3).
- `effective_bit_depth()`: AVIF forced 8-bit; JXL honors 16-bit; unchanged for the original four.
- `settings/dto.rs`: persisted roundtrip incl. AVIF/JXL + effort; **`#[serde(default)]` migration
  test** — legacy JSON without `effort` deserializes to `Balanced`.

**Encode tests (extend `tests/encode_roundtrip.rs`):**

- **AVIF — structural check, not decode.** Decoding AVIF in a test would pull `dav1d` (a **C
  toolchain**) via `image`'s `avif-native` feature, which would defeat the pure-Rust premise and
  break CI. Instead: encode a small `RenderedImage` to AVIF and assert the byte stream is non-empty
  and carries a valid ISOBMFF `ftyp` box with the **`avif`** major brand (a header/magic check).
  This proves the encoder ran and produced a well-formed container without any C dev-dependency.
- **JPEG-XL — true round-trip.** Encode a small `RenderedImage` at **8-bit and 16-bit** → decode
  back via **`jxl-oxide`** (pure Rust, already in-tree via `rawler`) → compare **lossless-exact**.
  Confirms zune-jpegxl output is standards-valid, round-trippable, and 16-bit survives. If wiring
  `jxl-oxide` as a dev-dependency proves awkward, fall back to the same `ftyp`/JXL-signature
  structural check as AVIF (recorded as the fallback, not the goal).

**egui UI** (6-format combo, Effort enable/disable, single + batch flows): `cargo build` + clippy +
the **author's hands-on visual test**. No golden tests for egui rendering.

**Gate:** `cargo fmt --check` + `cargo clippy --workspace --all-targets -- -D warnings` +
`cargo test --workspace` green → **then STOP and hold for the author's (Jann's) hands-on visual
test of the running app** before finishing/merging the branch (CLAUDE.md "Finishing a branch").

## 10. Decisions recorded (resolved during brainstorming, 2026-07-04)

| Question | Decision | Rationale |
|---|---|---|
| Encoder strategy / libjxl gating | **Pure-Rust only** — `ravif` (AVIF) + `zune-jpegxl` (JXL); no libjxl, no feature flag | CI uses `--all-features`, so a default-off flag wouldn't spare CI from the C toolchain; pure-Rust needs no gating and CI stays green unchanged. Matches "quality secondary" + all-Rust tree. |
| Whether JXL lossless is offered | **Lossless is the only JXL mode** | `zune-jpegxl` is lossless-only; lossy JXL (libjxl) is a future toolchain decision, out of scope. |
| AVIF quality vs effort UI | **Quality slider (reused) + new Effort selector** (Fast/Balanced/Best → ravif speed 10/6/3) | User choice; gives size-vs-time control without exposing speed 1 (“very very slow”). |
| JXL bit depth | **8-bit + 16-bit** (joins TIFF/PNG); 8-bit default | User choice; true lossless archival from the 16-bit render path. AVIF stays 8-bit (ravif). |
| ICC embedding (AVIF/JXL) | **Untagged + one informational warning** | Neither encoder embeds ICC; pixels are converted to the output space; reuses Spec 3 §10 untagged fallback. |
| EXIF on new containers | **Best-effort** (attempt; warn on failure) | Existing `little_exif` behavior; never fatal. |
| Effort per-control reset | **No reset arrow** (segmented control, default Balanced) | Export settings form is a config surface, not a Develop editing control; matches the existing (reset-less) Quality slider. |
| CI / build-gating | **No change** — no feature flag, no toolchain | Pure-Rust deps; CI green under `--all-features` as-is. |
| Engine/contract changes | **None** — encode-tail + UI only | Honors §5 contracts §1–5 and the licensing tiers (§3.1). |
