## 1. Summary

Spec 4.1 is the app-only polish phase. The map scoped it as "fix the before/after split's
missing icon + feedback, plus a grab-bag of small polish." A screenshot-driven walk of every
screen expanded the grab-bag into a coherent set of UX fixes and two genuine features (a real
**Settings system with persistence** and **fully remappable keybindings**). Everything here lives
in **`ferrolite-app` only**: no engine/photo-crate edits, and no new *workspace* crate enters the
dependency tree.

The work splits into five workstreams:

- **A. Settings core + persistence** — a `settings.json` store (keymap, export settings, filter,
  and several preferences), loaded at startup, saved off the UI thread. Foundational.
- **B. Keymap + full remap** — a central `Action → Chord` keymap that all shortcuts route through,
  persisted, with a rebinding UI.
- **C. Chrome** — make the titlebar menus (File/Edit/Photo/View/Help) functional, surface keyboard
  shortcuts in menus + tooltips, add a Help modal, and fix the footer margins.
- **D. Develop polish** — fix the adjustment-panel scroll bug; fix the before/after split (icon,
  auto-fit at 1:1, `Y` toggle, visible active state).
- **E. Tone-curve overhaul** — reliable point grabbing, discoverable delete, and a clear reset.

## 2. Fixed constraints carried in (from the map — do not re-litigate)

- **Tier / deps (§3.1):** 4.1 is `ferrolite-app` (photo tier). `serde` + `serde_json` are added to
  `ferrolite-app/Cargo.toml`; **both are already `[workspace.dependencies]`**, so no new crate
  enters the tree. **No `serde` is added to engine-tier crates** (`ferrolite-image` etc.) — the
  persistence layer uses app-side DTOs to serialize external types (see §3.A).
- **§5 contracts honored:**
  - *Job submission is universal (§1):* the settings write goes through `ferrolite-jobs` (like
    `spawn_ops_write`); the UI thread never does the file I/O.
  - *Catalog is a cache (§2):* settings live in their **own** `settings.json`, never in the
    catalog DB. Nothing rebuildable-from-files moves into the catalog.
  - Contracts §3/§4/§5 (decode products / GPU executor / VT) are untouched — this is UI-only.
- **CLAUDE.md rules (§3.4):**
  - *Responsiveness/threading:* no multi-ms work on the update thread; the settings save is a job.
  - *Per-control reset:* each remappable keybinding row gets its own reset; the tone curve keeps
    its own reset (relocated + written out, see §3.E). Existing sliders keep their reset column.
  - *Finishing a branch:* green workspace gate is necessary but not sufficient — **hold for the
    author's hands-on visual test** before finishing.

## 3. Design by workstream

### 3.A Settings core + persistence *(foundational)*

**New module** `ferrolite-app/src/settings/` (small, focused files):

- `mod.rs` — the `Settings` struct + load/apply glue.
- `keymap.rs` — `Action`, `Chord`, `Keymap` (§3.B).
- `dto.rs` — serializable mirrors of external types + `From`/`Into` mappings.
- `persist.rs` — path resolution, read, and the off-thread write job.
- `ui.rs` — the Settings window (general + keyboard tabs).

**`Settings` struct** (all fields `#[serde(default)]` so old/partial files load cleanly):

```rust
struct Settings {
    keymap: Keymap,                 // §3.B
    export: PersistedExport,        // DTO ↔ ferrolite_export::ExportOptions
    filter: PersistedFilter,        // DTO ↔ FilterState (persisted subset)
    working_space: PersistedWorkingSpace, // default Develop working space
    grid_size: f32,                 // Library thumbnail-size slider default
    confirm_remove: bool,           // gate the remove-confirmation modal (default true)
    restore_session: bool,          // reopen last folder/module on launch (default false)
    last_module: PersistedModule,   // only used when restore_session
    last_folder: Option<PathBuf>,   // only used when restore_session
}
```

**Storage location:** `%LOCALAPPDATA%/ferrolite/settings.json` (same base dir as `default_db_path`
and the diag logs). Path resolution reuses the existing `LOCALAPPDATA` logic; falls back to the
temp dir if unset (as diag does). Missing file → `Settings::default()`.

**Load:** in `AppState::new()`, after the catalog opens. Applied to initial state: `filter`,
`grid_size`, `working_space` seed their live fields; `export` seeds the export module's
`ExportOptions`; `restore_session` (if true) reopens `last_folder` **through the existing ingest/
scan job path** (never a synchronous walk on the UI thread) and selects `last_module`.

**Save:** a `settings::persist::save(settings)` that serializes to JSON and writes on a
`ferrolite-jobs` job (Background priority), mirroring `develop/ops_persist.rs::spawn_ops_write`.
Triggered on change via a `settings_dirty` flag coalesced per frame (write at most once per short
debounce window), plus a best-effort save in `eframe::App::on_exit`/`save` if invoked. We do **not**
rely on an exit hook firing — save-on-change is the source of truth.

**DTOs (`dto.rs`)** — why: `Flag`/`Rating` live in engine-tier `ferrolite-image`, and we must not
add `serde` there (§3.1). `ExportOptions`/`WorkingSpace`/filter enums live in photo-tier crates, but
routing all persisted types through app-side DTOs keeps 4.1 self-contained and touches no other
crate. Each DTO is a plain serde struct/enum with `From<External>` and `Into<External>` (or a
`fn to_external`/`fn from_external`) and a **round-trip unit test**.

- `PersistedExport` ↔ `ferrolite_export::ExportOptions` (format, output space, bit depth, quality,
  resize, copy-EXIF, embed-ICC, strip-metadata).
- `PersistedFilter` ↔ persisted subset of `FilterState` (sort key + desc, min rating + cmp, flags,
  tag ids, tag mode, subfolders, metadata toggle). Tag ids that no longer exist in the catalog are
  dropped on load.
- `PersistedWorkingSpace` ↔ `ferrolite_color::WorkingSpace`; `PersistedFlag` ↔ `ferrolite_image::Flag`;
  `PersistedModule` ↔ `module::Module`; plus the sort/rating-cmp/tag-mode enums.

### 3.B Keymap + full remap

- **`Action`** — an enum of every bindable command: `CloseViewer`, `OpenImage`, `SelectAll`,
  `Rating0..Rating5`, `FlagPick`, `FlagReject`, `AddToQueue`, `PrevImage`, `NextImage`,
  `HoldBeforePeek` (momentary), `ToggleSplitCompare`, `Undo`, `Redo`, `OpenSettings`, `OpenHelp`.
- **`Chord { key: Key, mods: Modifiers }`** — serializable; a `Display`/parse pair renders it
  ("Ctrl+Shift+Z", "Q", "←") for menus, tooltips, and the rebinding UI.
- **`Keymap { map: BTreeMap<Action, Chord> }`** with `Keymap::defaults()` reproducing today's
  bindings exactly:

  | Action | Default | Context (unchanged) |
  |---|---|---|
  | CloseViewer | `Esc` | always |
  | OpenImage | `Enter` | Library, no viewer, no modal, no text focus |
  | SelectAll | `Ctrl+A` | Library grid, no viewer/modal/text focus |
  | Rating0..5 | `0`..`5` | selection or open viewer, no text focus |
  | FlagPick / FlagReject | `I` / `O` | same as rating |
  | AddToQueue | `Q` | viewer/selection context |
  | PrevImage / NextImage | `←` / `→` | Develop |
  | HoldBeforePeek | `\` | Develop, **hold semantics** |
  | ToggleSplitCompare | `Y` | Develop (**new**) |
  | Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z` (+ `Ctrl+Y` alias for redo) | edit context |
  | OpenSettings | `Ctrl+,` | always |
  | OpenHelp | `F1` | always |

- **Dispatch:** the inline `ctx.input(|i| i.key_pressed(Key::X))` checks in `app.rs` are replaced by
  `keymap.pressed(ctx, Action::X)` (edge) and `keymap.held(ctx, Action::HoldBeforePeek)` (level, for
  the `\` peek). **The surrounding context gates stay exactly as they are** — only the chord literal
  moves into the keymap. `HoldBeforePeek` is bindable but always evaluated with hold semantics.
- **Redo** keeps its dual trigger (`Ctrl+Shift+Z` and `Ctrl+Y`); the keymap models the primary
  chord and the app keeps the `Ctrl+Y` alias check (documented).
- **Rebinding UI** (Settings → Keyboard tab): actions grouped by category (Navigation, Rating &
  Flags, Develop, Editing, App). Each row: action label · current chord · **Rebind** button
  (captures the next chord via `ctx.input` on the following frame) · **per-row reset arrow**
  (`draw_reset_arrow`) restoring that action's default. **Conflict detection:** assigning a chord
  already used by another *active-in-the-same-context* action shows an inline warning and blocks the
  save until resolved (no silent stealing). A "Reset all shortcuts" affordance restores
  `Keymap::defaults()`.

**Pure + tested:** `Keymap::defaults()` covers every `Action` variant (exhaustive test); chord
format/parse round-trips; conflict detection; serde round-trip; unknown/al­tered JSON tolerated.

### 3.C Chrome: menus, shortcut labels, Help modal, footer

**Menus** — extend `chrome::MenuAction` and `chrome::title_bar`. Every item with a bound action
shows its shortcut **right-aligned, pulled live from the keymap** (so remaps stay reflected). Menus
respect enablement (e.g. Undo greys out with empty history):

- **File:** `Purge preview cache` (exists) · `Settings…` · `Exit`
- **Edit:** `Undo` · `Redo` · `Select all`
- **Photo:** `Export…` · `Add to export queue` · `Previous image` · `Next image`
- **View:** `Library` · `Develop` · `Export` · `Before/After split` (Y) · `Fit` · `1:1`
- **Help:** `Keyboard shortcuts` · `About Ferrolite` → opens the Help modal

New `MenuAction` variants (e.g. `OpenSettings`, `OpenHelp`, `Exit`, `Undo`, `Redo`, `SelectAll`,
`PrevImage`, `NextImage`, `SwitchModule(Module)`, `ToggleSplit`, `ZoomFit`, `ZoomActual`) are handled
in the app's existing `match menu_action` site, routing to the same code paths the keyboard uses.

**Tooltips** — footer icon buttons (rating stars, flags, export, tags) and the split toggle gain
`.on_hover_text` including the current shortcut from the keymap.

**Help modal** — a modal overlay following the existing remove-confirmation modal pattern
(`Area`/`Window` + dimmed backdrop, `Esc`/click-away to close). Content: a **live keyboard-shortcut
reference** built from the keymap (grouped like the rebinding UI) + an **About** block (app name,
`v0.0.1`, license line). Opened from Help → Keyboard shortcuts / About and via `F1`.

**Footer margin** — the status-bar `TopBottomPanel::bottom("status")` frame gets an inner margin
(`egui::Margin::symmetric(12.0, 0.0)`) so the left EXIF text isn't flush to the window edge. Fill
stays `BG_TITLEBAR`.

### 3.D Develop polish

- **Adjustment-panel scroll (bug):** inside `SidePanel::right("develop_adjust")`, wrap the
  `adjustment_panel::show(...)` body in `egui::ScrollArea::vertical().auto_shrink([false, false])`
  so Detail/Geometry (and future sections) are reachable. The histogram/working-space header may
  stay pinned above the scroll area or scroll with it — chosen during implementation to match the
  design system; default is everything scrolls together for simplicity.
- **Before/after split:**
  - **Icon:** a painter-drawn split-rectangle glyph in `library/icons.rs` (a rounded rect with a
    vertical divider, one half tinted) replacing the `\u{21D4}` placeholder in
    `develop_filter_bar.rs`. Matches the no-font-glyph icon grammar (IBM Plex Sans lacks symbols).
  - **Auto-fit at 1:1:** when `ToggleSplitCompare` turns the split **on** while the view is at/near
    1:1 (`show_full`), ease/set the view to `ViewTransform::fit(dims, viewport)` so the divider
    appears immediately — no silent suppression. The existing `eprintln!` suppression note is
    removed (or downgraded to a dev-only diag). The split remains preview-tier; auto-fit sidesteps
    the dead-end without VT work (that stays Spec 4.5).
  - **Shortcut:** `Y` toggles split-compare (via keymap, Develop context). `\` peek unchanged.
  - **Active state:** the toggle renders with a clearly lit/pressed appearance when active.
- **Existing divider/handle/cursor** (white line, handle circle, `ResizeHorizontal` on hover) are
  kept; only discoverability of the *toggle* and the 1:1 behavior change.

### 3.E Tone-curve overhaul *(`develop/curve_widget.rs`; `curve_math.rs` largely unchanged)*

The pure math (`insert_point`/`move_point`/`delete_point`/`nearest_point`, endpoints pinned) is
correct and tested; the problems are all in the interaction/presentation layer.

- **Reliable grabbing:** increase the hit radius (≈`0.06–0.07` normalized) and point-dot radius
  (`3.5 → ~5`); **hover-highlight** the point under the cursor (enlarge + brighten) so it's obvious
  what will be grabbed. Insert a new point **only** when the click is clearly away from every
  existing point (no `nearest_point` hit within radius) — fixing "moving a point creates a new one."
- **Discoverable delete (all three gestures):**
  - **Click selects** a point (store selected index in `ui.memory`; highlight it).
  - **Delete / Backspace** removes the selected point.
  - **Double-click** on a point removes it.
  - **Right-click** on a point removes it (existing path retained).
  - Endpoints (first/last) remain non-deletable (existing `delete_point` guard).
- **Reset — relocated + written out:** remove the in-corner reset icon. Add a **written-out
  "Reset" button underneath the curve editor**, styled like the Basic section's "Reset" (text
  button, dim when at identity, active when modified). This is the curve's **per-control reset**
  (honors the CLAUDE.md rule) and is visually consistent with the panel's other section resets.
- **Optional nicety:** a small input→output coordinate readout while dragging (kept only if it
  doesn't clutter; decided during the visual pass).
- **Rendering:** verify the widget's polyline matches the pipeline's curve evaluation and keep them
  consistent. **No change to the pipeline** (photo tier) — display-only.
- **Purity:** the new "insert-vs-grab" decision is extracted as a pure helper in `curve_math`
  (input: points, cursor, hit radius → grab index | insert) with unit tests.

## 4. Testing strategy

Per the rust testing rules (TDD; pure logic covered; egui presentation visual-tested).

**Unit-tested (pure):**
- `Keymap::defaults()` binds **every** `Action` variant (exhaustive); chord `Display`/parse
  round-trip; conflict detection (dup in same context flagged, different contexts allowed);
  serde round-trip of `Keymap`.
- `Settings` serde round-trip; **missing-field tolerance** (a JSON with a subset of fields loads and
  fills defaults); write-then-read equals original.
- Every DTO (`PersistedExport`/`Filter`/`WorkingSpace`/`Flag`/`Module`/sort/rating-cmp/tag-mode)
  `From`→`Into` round-trip equals the source; stale tag ids dropped on filter load.
- Curve "insert-vs-grab" helper: returns grab for a click within radius of a point, insert for a
  click clearly away; selected-point delete respects endpoint protection (reuses `curve_math` tests).

**Visual-tested (held for the author):** menus + shortcut labels, Help modal, footer margin,
adjustment-panel scroll, split icon + auto-fit + active state + `Y`, tone-curve grab/delete/reset
feel, Settings window + rebinding UX + conflict warnings.

**Gate:** `cargo fmt --check` + `cargo clippy --workspace --all-targets -- -D warnings` +
`cargo test --workspace` green — **then STOP and hold for the author's hands-on visual test** before
finishing/merging (CLAUDE.md finishing rule).

## 5. Recommended implementation phasing (for `writing-plans`)

1. **Settings core + persistence scaffold** — `Settings` struct, JSON path/read, off-thread write
   job, DTOs (+ their tests). No behavior change yet beyond load/save plumbing.
2. **Keymap** — `Action`/`Chord`/`Keymap` + `defaults()`; route every existing shortcut through the
   keymap (behavior-preserving) + persist. Tests.
3. **Wire persisted preferences** — export settings, filter, working space, grid size,
   confirm-remove gating, restore-session (through the ingest job path).
4. **Chrome menus + shortcut labels + tooltips** — functional File/Edit/Photo/View/Help; shortcuts
   shown live from the keymap.
5. **Help modal** — shortcut reference (from keymap) + About; F1 + Help menu.
6. **Settings window** — general tab (the preferences) + keyboard tab (rebinding UI with per-row
   reset + conflict detection).
7. **Develop** — adjustment-panel scroll fix; before/after (icon, auto-fit, `Y`, active state).
8. **Tone-curve overhaul** — grabbing, delete gestures, relocated written-out reset.
9. **Footer margin** — trivial; folds in anywhere.

Order rationale: A→B are foundational (menus, Help, and the rebinding UI all read the keymap;
several preferences read Settings). D/E/9 are independent and can land in any order after the
foundation.

## 6. Risks & flags

- **Full keybind remap is the largest single piece.** The behavior-preserving routing (phase 2)
  must keep every context gate; the rebinding UI (phase 6) needs solid conflict handling. Mitigation:
  land phase 2 as a pure refactor verified by the existing behavior + new keymap tests before the UI.
- **Restore-session** must reopen the last folder via the existing ingest/scan **job** path — never a
  synchronous directory walk on the UI thread (CLAUDE.md). If the folder is gone, log and skip.
- **eframe exit hook** is not guaranteed; save-on-change is authoritative, exit save is best-effort.
- **Scope:** this is a bigger 4.1 than the map's estimate. It stays app-only and in-tier, but the
  plan should be phased so partial progress is shippable/reviewable.
